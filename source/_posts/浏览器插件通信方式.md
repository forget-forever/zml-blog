在浏览器插件开发中，`content script`和`service worker`之间的通信是一个常见的需求。虽然这两个组件在不同的上下文中运行（一个是在页面上运行的脚本，另一个是后台线程），但它们可以通过一些方法进行交互。

## 浏览器插件content script

浏览器的content script提供两种模式
|| 注入到页面中的脚本 | 独立的后台线程 |
|---| --- | --- |
|Javascript| 共享变量空间  | 与网页隔离 |
|document| 共享  | 共享 |
|Chrome|与网页一致，智能访问runtime中的变量|可以访问onMessage|

  通常情况下，我们会使用第二种方式，即在独立的后台线程中运行service worker。
  但是，这种情况下就会遇到js不互通的问题，content script与网站的js的window无法共享

## 通信方式

在浏览器插件中，涉及到通信的主要有以下几个角色：

- **网页（Web Page）**：用户正在浏览的普通网页
- **Content Script**：注入到网页中运行的脚本，可访问 DOM，但 JS 上下文与网页隔离
- **Service Worker（Background）**：插件后台线程，可调用大多数 Chrome Extension API
- **Popup / Options Page**：插件的弹出页面或选项页，拥有独立的 JS 上下文

它们之间的通信关系如下：

```text
网页 <--window.postMessage--> Content Script <--chrome.runtime.sendMessage--> Service Worker
                                                                                    ↑
                                                          Popup / Options Page ------
```

### 1. Content Script ↔ Service Worker（chrome.runtime 消息通信）

这是最常用的通信方式，使用 `chrome.runtime.sendMessage` 发送消息，使用 `chrome.runtime.onMessage` 接收消息。

#### Content Script 发送消息给 Service Worker

```javascript
// content_script.js
chrome.runtime.sendMessage({ action: 'getData', payload: { key: 'value' } }, (response) => {
  console.log('收到 Service Worker 的回复：', response)
})
```

```javascript
// service_worker.js (background.js)
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.action === 'getData') {
    console.log('收到来自 Content Script 的消息：', message.payload)
    // 处理数据...
    sendResponse({ result: 'success', data: '这是返回数据' })
  }
  // 如果 sendResponse 是异步调用，需要返回 true 保持消息通道
  return true
})
```

#### Service Worker 主动发消息给 Content Script

Service Worker 无法直接调用 `chrome.runtime.sendMessage` 给 Content Script，需要先获取目标 Tab 的 ID，再通过 `chrome.tabs.sendMessage` 发送：

```javascript
// service_worker.js
async function sendMessageToContentScript(tabId, message) {
  const response = await chrome.tabs.sendMessage(tabId, message)
  console.log('Content Script 回复：', response)
}

// 获取当前活跃 Tab 并发送消息
chrome.tabs.query({ active: true, currentWindow: true }, (tabs) => {
  if (tabs[0]) {
    chrome.tabs.sendMessage(tabs[0].id, { action: 'updateUI', data: '新数据' })
  }
})
```

```javascript
// content_script.js
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.action === 'updateUI') {
    console.log('收到 Service Worker 的指令：', message.data)
    sendResponse({ status: 'done' })
  }
  return true
})
```

### 2. 网页 ↔ Content Script（window.postMessage）

由于网页的 JS 与 Content Script 的 JS 上下文隔离，它们之间无法直接共享变量，但它们共享同一个 `window` 对象，因此可以通过 `window.postMessage` 进行通信。

#### 网页发消息给 Content Script

```javascript
// 网页中的脚本 (page.js)
window.postMessage(
  { source: 'web-page', action: 'requestToken', payload: { userId: 123 } },
  '*' // 生产环境建议指定具体 origin
)
```

```javascript
// content_script.js
window.addEventListener('message', (event) => {
  // 安全校验：确保消息来自当前页面，而不是其他插件或 iframe
  if (event.source !== window) return
  if (event.data?.source !== 'web-page') return

  if (event.data.action === 'requestToken') {
    console.log('收到网页的消息：', event.data.payload)
    // 可继续转发给 Service Worker
    chrome.runtime.sendMessage({ action: 'getToken', ...event.data.payload })
  }
})
```

#### Content Script 回消息给网页

```javascript
// content_script.js
window.postMessage({ source: 'content-script', action: 'tokenResult', token: 'abc123' }, '*')
```

```javascript
// 网页中的脚本 (page.js)
window.addEventListener('message', (event) => {
  if (event.data?.source !== 'content-script') return
  if (event.data.action === 'tokenResult') {
    console.log('收到插件返回的 token：', event.data.token)
  }
})
```

### 3. 网页 → Content Script → Service Worker（完整链路）

将上面两种方式结合，可以实现网页与 Service Worker 之间的完整通信链路：

```javascript
// 网页 page.js：发起请求
window.postMessage({ source: 'web-page', action: 'fetchUserInfo', userId: 42 }, '*')

// 监听插件的回复
window.addEventListener('message', (event) => {
  if (event.data?.source === 'content-script' && event.data.action === 'userInfoResult') {
    console.log('用户信息：', event.data.result)
  }
})
```

```javascript
// content_script.js：中间桥梁
window.addEventListener('message', (event) => {
  if (event.source !== window || event.data?.source !== 'web-page') return

  // 转发给 Service Worker
  chrome.runtime.sendMessage(event.data, (response) => {
    // 将 Service Worker 的回复转发回网页
    window.postMessage({ source: 'content-script', action: 'userInfoResult', result: response }, '*')
  })
})
```

```javascript
// service_worker.js：处理业务逻辑
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.action === 'fetchUserInfo') {
    fetch(`https://api.example.com/user/${message.userId}`)
      .then((res) => res.json())
      .then((data) => sendResponse(data))
    return true // 异步 sendResponse 必须返回 true
  }
})
```

### 4. 长连接通信（chrome.runtime.connect）

对于需要持续通信的场景（如实时数据推送），可以使用 `chrome.runtime.connect` 建立长连接，避免每次都重新建立消息通道：

```javascript
// content_script.js：建立长连接
const port = chrome.runtime.connect({ name: 'data-stream' })

port.postMessage({ action: 'subscribe', topic: 'price-updates' })

port.onMessage.addListener((message) => {
  console.log('收到推送数据：', message)
})

port.onDisconnect.addListener(() => {
  console.log('连接已断开')
})
```

```javascript
// service_worker.js：监听长连接
chrome.runtime.onConnect.addListener((port) => {
  if (port.name === 'data-stream') {
    port.onMessage.addListener((message) => {
      if (message.action === 'subscribe') {
        // 模拟持续推送数据
        const timer = setInterval(() => {
          port.postMessage({ price: Math.random() * 100 })
        }, 1000)

        port.onDisconnect.addListener(() => {
          clearInterval(timer)
        })
      }
    })
  }
})
```

### 5. 使用 chrome.storage 共享数据

除了消息传递，也可以通过 `chrome.storage` 在各组件间共享数据，并通过 `onChanged` 监听变更：

```javascript
// service_worker.js：写入数据
chrome.storage.local.set({ userConfig: { theme: 'dark', lang: 'zh' } })
```

```javascript
// content_script.js 或 popup.js：读取数据
chrome.storage.local.get('userConfig', (result) => {
  console.log('配置数据：', result.userConfig)
})

// 监听数据变化
chrome.storage.onChanged.addListener((changes, area) => {
  if (area === 'local' && changes.userConfig) {
    console.log('配置已更新：', changes.userConfig.newValue)
  }
})
```

## 通信方式对比

| 通信方式 | 适用场景 | 优点 | 缺点 |
| --- | --- | --- | --- |
| `chrome.runtime.sendMessage` | Content Script ↔ Service Worker / Popup | 简单易用，支持回调 | 一次性通信，无法持续推送 |
| `chrome.tabs.sendMessage` | Service Worker → Content Script | 可指定目标 Tab | 需要知道 Tab ID |
| `window.postMessage` | 网页 ↔ Content Script | 跨越 JS 上下文隔离 | 需要做 source 校验，安全性较低 |
| `chrome.runtime.connect` | 需要持续通信的场景 | 长连接，适合实时数据 | 实现稍复杂，连接需要管理 |
| `chrome.storage` | 共享配置、状态同步 | 持久化存储，自动同步 | 非实时，适合低频数据 |

## 注意事项

1. **异步 sendResponse**：在 `onMessage` 回调中，如果 `sendResponse` 是异步调用（如包含 `await` 或 `fetch`），必须在监听函数末尾 `return true`，否则消息通道会在异步操作完成前关闭。

2. **postMessage 安全校验**：使用 `window.postMessage` 时，务必校验 `event.source === window` 和消息来源标识，防止恶意网页伪造消息。

3. **Service Worker 生命周期**：MV3 中 Service Worker 是按需唤醒的，不能依赖其持有的内存状态。长期存储应使用 `chrome.storage`。

4. **Manifest 权限声明**：使用 `chrome.tabs.sendMessage` 需要在 `manifest.json` 中声明 `tabs` 权限；使用 `chrome.storage` 需要声明 `storage` 权限。

```json
{
  "permissions": ["tabs", "storage", "activeTab"]
}
```
